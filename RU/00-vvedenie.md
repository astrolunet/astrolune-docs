# 0. Введение в проект

## 0.1. Что это

Astrolune — децентрализованная блокчейн-сеть с собственной консенсус-моделью
**PoTB** (Proof of Trusted Behavior), собственной виртуальной машиной для
исполнения смарт-контрактов, двухуровневой системой языков контрактов
(Trocto/Regol) и, в перспективе, собственной инфраструктурой: DNS-зоной
`.lune`, слоем хранения данных и прокси-слоем.

## 0.2. Цели проекта

- **Анти-Sybil без покупаемого ресурса.** Вес узла в сети определяется
  временем честной работы и положением в графе доверия, а не хэшрейтом или
  застейканным капиталом.
- **Детерминированное исполнение контрактов.** На каждом узле — одинаковый
  результат; это основа консенсуса над состоянием сети.
- **Производительность на горячем пути.** Консенсус, сеть, криптография,
  движок хранения и виртуальная машина написаны на C; инструментарий для
  разработчиков — на C++.
- **Безопасность контрактов по умолчанию.** Высокоуровневый язык Trocto
  закрывает типичные классы уязвимостей контрактов на уровне компилятора.

## 0.3. Границы первой фазы

**В фокусе сейчас:**
1. Виртуальная машина (спецификация, набор инструкций, модель газа).
2. Модель транзакций и состояния.
3. Интеграция VM с консенсусом PoTB.

**Сознательно отложено (на уровне каркасов-skeleton):** слой хранения
(storage), прокси-слой, DNS-зона `.lune`. Это спроектированные заглушки с
письменно зафиксированными открытыми вопросами, а не забытые части — см.
[06-servisy-otlozhennye.md](06-servisy-otlozhennye.md).

## 0.4. Нефункциональные требования

| Требование | Целевое значение |
|---|---|
| Время блока | 400 мс – 1 с (честный диапазон; зависит от того, какая ветка VDF будет выбрана) |
| Детерминизм VM | 100% — никаких недетерминированных операций во время исполнения |
| Размер комитета | 100 узлов, частичная ротация ~10% за блок |
| Пересчёт графа доверия | раз в эпоху (1 день) |
| Основные языки ядра | C (горячий путь), C++ (инструментарий) |

## 0.5. Принципы проектирования

- **Честность в отношении рисков.** Открытые проблемы фиксируются как
  открытые, а не выдаются за решённые (см. раздел 8 и раздел 1 про PoTB).
- **Разделяемые границы модулей.** У каждого компонента чёткий интерфейс, что
  позволяет разрабатывать и тестировать части ядра независимо.
- **Спецификация прежде кода.** Спецификация фиксирует контракты между
  модулями до их реализации.

  Единственное сознательное исключение — там, где реализованный заголовок и
  документ расходятся: заголовок побеждает, потому что именно его
  исполняют узлы. Такие случаи считаются ошибками документа и перечислены в
  [08-status-realizatsii.md](08-status-realizatsii.md).

## 0.6. Уровни узлов — коротко

Подробно — в разделе [07-trebovaniya-validatora.md](07-trebovaniya-validatora.md).

| Уровень | Название | Условие входа |
|---|---|---|
| 1 | Full/Relay-узел | Запустил клиент — сразу |
| 2 | Кандидат в комитет | TBS выше минимального порога (недели работы) |
| 3 | Полноценный валидатор | TBS и TGW выше порогов, нет штрафов в истории |

## 0.7. Термины

Ниже — только базовый набор для быстрой навигации; полный словарь терминов
рассыпан по соответствующим разделам этого комплекта документации (каждая
аббревиатура вводится и определяется там, где впервые содержательно
используется).

| Термин | Расшифровка | Определение |
|---|---|---|
| **PoTB** | Proof of Trusted Behavior | Консенсус-модель сети: право финализировать блоки определяется временем честной работы, наблюдаемым поведением и положением в графе доверия, а не покупаемым ресурсом. |
| **TBS** | Time-Behavior Score | Компонент веса узла: логарифм аптайма × корректности, плюс бонус за лояльность после года работы. |
| **TGW** | Trust Graph Weight | Компонент веса узла: положение в графе доверия (SybilRank + TDI + внешние челленджи). |
| **NDM** | Network Diversity Multiplier | Мягкий множитель по разнообразию ASN. Вспомогательный слой — обходится резидентными прокси. |
| **COD** | Cluster Ownership Dampening | Анти-корреляционный множитель: подавляет совокупный вес статистически связанных групп узлов. |
| **VRF** | Verifiable Random Function | Верифицируемая случайная функция; выбирает комитет на каждый блок. |
| **VDF** | Verifiable Delay Function | Функция с верифицируемой задержкой; защищает сид от манипуляции по времени. |
| **BFT** | Byzantine Fault Tolerance | Класс алгоритмов финализации, устойчивых к доле злонамеренных участников. |
| **Комитет** | — | Набор из 100 узлов, выбранных VRF, финализирующий блоки. Частичная ротация ~10% за блок. |
| **Эпоха** | — | Период (1 день), по итогам которого пересчитывается TGW и выдаются внешние челленджи. |
| **Кворум** | — | Голоса, необходимые для BFT-финальности: `floor(2n/3) + 1`. |
| **ALVM** | Astrolune VM | Виртуальная машина сети — детерминированно исполняет байткод контрактов на каждом узле. |
| **Gas** | — | Единица учёта вычислительных ресурсов, потраченных при исполнении контракта. |
